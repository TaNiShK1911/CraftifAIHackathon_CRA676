# SiteGuard — Backend Implementation Plan

**Project:** SiteGuard, a Workplace Safety Sentinel (Suggested Track 1) for the Embedded SF: CraftifAI Physical AI Hackathon, **Track A — PipeGen**.
**Role of the backend:** consume the output of the PipeGen/DeepStream pipeline (MQTT + JSON metadata), turn raw detections into deduplicated safety **incidents**, store them, and serve them to the dashboard in real time.

> **Deep Integration rule (disqualification risk).** All perception (detection, tracking, zone/PPE analytics, TensorRT compilation) must be produced by the **PipeGen pipeline**. The backend must contain **no model inference and no OpenCV detection code**. It only ingests, correlates, stores and serves. If a reviewer greps the repo for `torch`, `ultralytics` or `cv2.dnn`, they should find nothing.

## 4. Canonical event schema

The adapter converts whatever PipeGen emits into this. Everything downstream depends only on this shape.

```python
class CanonicalEvent(BaseModel):
    event_id: str            # uuid4 generated by adapter
    ts: datetime             # source timestamp if present, else ingest time (UTC)
    source_id: str           # camera / stream id, e.g. "cam0"
    frame_id: int | None
    track_id: int | None     # tracker id if PipeGen tracking is enabled
    label: str               # "person", "no_hardhat", "no_vest", ...
    confidence: float        # 0..1
    bbox: tuple[float, float, float, float] | None  # x, y, w, h normalized 0..1
    zone_id: str | None      # set if PipeGen ROI/zone analytics reports it
    attributes: dict         # anything else, kept verbatim
    raw: dict                # original payload (stored for audit/debug)
```

### Event types derived from labels (configurable in `adapter.yaml`)

| Incident type | Trigger | Default severity |
|---|---|---|
| `ZONE_INTRUSION` | person event with a `zone_id` in the hazard-zone list | HIGH |
| `PPE_VIOLATION` | label in `{no_hardhat, no_vest}` or person lacking required PPE attribute | MEDIUM |
| `LOITERING` | same track in a hazard zone longer than `loiter_seconds` | escalates to CRITICAL |

## 5. Data model (SQLite)

```
events(id PK, ts, source_id, frame_id, track_id, label, confidence,
       bbox_json, zone_id, raw_json)
incidents(id PK, type, severity, status, source_id, track_id, zone_id,
          first_seen, last_seen, event_count, max_confidence,
          snapshot_path, ack_by, ack_at)
pipeline_runs(id PK, created_at, model_name, precision, engine_path,
              fps, latency_ms, power_w, accuracy_map, notes)
evidence(id PK, created_at, kind, title, file_path, description)
```

`incidents.status` ∈ `OPEN | ACKNOWLEDGED | RESOLVED`.
Indexes: `events(ts)`, `incidents(status, last_seen)`, `incidents(type)`.

## 6. Ingest layer

### 6.1 MQTT consumer
- Subscribes to a configurable topic filter (default `pipegen/#`; **set the real topic after running PipeGen once**).
- Auto-reconnect with exponential backoff (1s to 30s).
- Each message is parsed as JSON (a single object or an array), passed to `adapter.normalize()`, then to `rules.engine.handle()`.
- Malformed payloads are logged and counted (`/api/health` exposes `dropped_messages`); they never crash the loop.

### 6.2 JSON metadata tailer
- PipeGen can also write **JSON metadata files**. The tailer watches `PIPEGEN_OUTPUT_DIR` with `watchfiles`, reads new or appended files (JSON or JSONL), and feeds the same adapter path.
- Track the last-read byte offset per file so restarts do not re-ingest.
- Either MQTT or the tailer may be the primary source. Run both, and dedupe on `(source_id, frame_id, track_id, label)`.

### 6.3 Adapter (the one integration unknown)
`adapter.py` reads `config/adapter.yaml`, which maps raw keys to canonical fields using dotted paths:

```yaml
source_id: "camera_id"
frame_id:  "frame_num"
timestamp: "timestamp"        # epoch ms or ISO; adapter handles both
objects_path: "objects"       # list of detections inside one message
fields:
  track_id:   "tracker_id"
  label:      "class"
  confidence: "conf"
  bbox:       "bbox"          # [x, y, w, h] or [x1, y1, x2, y2]
  zone_id:    "roi"
bbox_format: "xyxy"           # xyxy | xywh
frame_size: [1920, 1080]      # used to normalize bbox
```

**Rule:** do not hard-code PipeGen's schema in Python. The first task after PipeGen produces output is to open a real message, then edit this YAML. Unit-test the adapter against a captured real sample saved in `tests/fixtures/`.

## 7. Rules engine (events to incidents)

State kept in memory, keyed by `(type, source_id, track_id, zone_id)`:

1. **Classify** each canonical event into zero or more candidate incident types (section 4).
2. **Debounce:** require `min_consecutive_frames` (default 5) of the same condition before opening an incident. This filters single-frame false positives.
3. **Open / update:** if no open incident for the key, create one (`OPEN`, snapshot requested). Otherwise update `last_seen`, `event_count`, `max_confidence`.
4. **Escalate:** if `last_seen - first_seen > loiter_seconds` for a zone intrusion, raise severity to CRITICAL and publish an `incident.escalated` message.
5. **Auto-close:** a background task every 2s resolves incidents with no new events for `quiet_seconds` (default 8). Set `RESOLVED` and publish `incident.closed`.
6. **Throttle storage:** persist only 1 raw event per `(key, 500 ms)` to keep SQLite small; counts still increment.
7. Every state change is pushed to `bus` (feeds SSE).

All thresholds live in `config.py`, overridable by env vars, so they can be tuned during the demo without code changes.

### Snapshots
- Preferred: use a frame or crop path if PipeGen's output references one.
- Fallback: the dashboard shows the time-synced position in the saved annotated PipeGen output video (`/media/video`). The backend does **no image processing**.

## 8. REST API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | broker connected, last message age, dropped count, DB ok |
| GET | `/api/events?limit=&since=&label=` | recent canonical events |
| GET | `/api/incidents?status=&type=&limit=` | incident list |
| GET | `/api/incidents/{id}` | detail incl. recent events |
| PATCH | `/api/incidents/{id}` | body `{status, ack_by}` for acknowledge or resolve |
| GET | `/api/stats/summary` | totals, open count, by-type, by-severity, last-hour |
| GET | `/api/stats/timeseries?bucket=1m&window=60m` | counts for charts |
| GET | `/api/zones` | zones from `zones.yaml` (for overlay drawing) |
| GET | `/api/stream` | **SSE**: `event`, `incident.opened`, `incident.updated`, `incident.closed` |
| GET | `/api/pipeline/runs` | precision and speed comparison rows |
| POST | `/api/pipeline/runs` | add a run (values copied from PipeGen's speed report) |
| GET / POST | `/api/evidence` | list or upload evidence (IR graph screenshot, speed report) |
| GET | `/media/*` | static: annotated video, snapshots, evidence images |

**Conventions:** JSON only, ISO-8601 UTC timestamps, error body `{ "detail": "..." }`, CORS allowed for the frontend origin, pagination via `limit` (max 200).

### SSE message format
```
event: incident.opened
data: {"id": 42, "type": "ZONE_INTRUSION", "severity": "HIGH", "track_id": 7, "zone_id": "crane_zone", "first_seen": "..."}
```
Heartbeat comment `: ping` every 15 s. The frontend reconnects automatically and refetches on reconnect.

## 13. Running locally next to the CUDA workload

The backend shares one machine with PipeGen/DeepStream, which owns the GPU. Keep it out of the way:

- **CPU only.** `requirements.txt` must not contain `torch`, `tensorrt`, `onnxruntime-gpu`, `opencv-python` or any CUDA package. Suggested pins: `fastapi`, `uvicorn[standard]`, `aiomqtt`, `watchfiles`, `sqlmodel`, `pydantic`, `pyyaml`, `pytest`, `httpx`.
- **Native venv for development**, Docker only for Mosquitto. This avoids container networking surprises (see `INTEGRATION.md` section 5A).
- **Light footprint:** the throttle in section 7 (one stored raw event per key per 500 ms) keeps CPU and disk use low while DeepStream runs at full speed. Use SQLite WAL mode (`PRAGMA journal_mode=WAL`) so the API can read while the ingest writes.
- **Paths:** `PIPEGEN_OUTPUT_DIR` and `MEDIA_VIDEO_PATH` must be absolute paths on the local disk, readable by the user running Uvicorn.
- **GPU metrics (optional):** the pipeline-runs endpoint takes numbers copied from PipeGen's speed report. If you also want live GPU stats on the dashboard, shell out to `nvidia-smi --query-gpu=utilization.gpu,memory.used,power.draw --format=csv,noheader` every 2 s from a small background task and expose it at `GET /api/system/gpu`. This does not import any CUDA library, so it stays within the Deep Integration rule.
- **Bind address:** `--host 0.0.0.0` only if a phone or second laptop needs to open the dashboard; otherwise `127.0.0.1`.
