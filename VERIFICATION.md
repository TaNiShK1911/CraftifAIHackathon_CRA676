## 2. Data Provenance Architecture

Every event, incident, and pipeline benchmark run contains a `data_origin` attribute:

| Value | Origin | Handling |
|---|---|---|
| `live` | Live MQTT / JSON tailer stream from running PipeGen DeepStream pipeline | Displayed with green `[LIVE]` chip; visible in live-only mode |
| `replay` | Re-published from capture using `scripts/replay.py` | Displayed with amber `[REPLAY]` chip |
| `seed` | Development seed data generated by `scripts/seed_demo.py --allow-synthetic` | Displayed with muted `[SYNTHETIC]` chip |

### UI & API Capabilities
- **API Filtering:** `GET /api/incidents?data_origin=live` and `GET /api/events?data_origin=live`.
- **Live Monitor Toggle:** Operators can filter the live incident feed between "All Origins" and "Live Only".
- **Incidents Table & Drawer:** Displays the `DataOriginChip` for every incident.
- **Pipeline Benchmarks Table:** Explicitly shows `Origin` column so imported benchmark reports are auditable.
- **Speed Report Importer (`backend/scripts/import_speed_report.py`):** Requires mandatory fields (`precision`, `fps`, `latency_ms`), never fills defaults, and marks imported runs as `data_origin="live"`.

Phases 2 and 3 require live artifacts from an NVIDIA GPU machine running PipeGen:

| Required File | Purpose |
|---|---|
| `captured/mqtt_sample.txt` | Raw MQTT telemetry captured via `mosquitto_sub -t '#' -v > captured/mqtt_sample.txt` |
| `captured/json_sample/` | Directory containing real JSON metadata output from PipeGen |

| `captured/speed_report.csv` | Real TensorRT speed report (FP32 / FP16 / INT8) |
| `captured/screens/` | Screenshots of the 5 PipeGen stages (Requirement, IR, Model, Compiler, Live Run) |
| `captured/RUN_NOTES.md` | Hardware specs: GPU, driver version, CUDA version, PipeGen version |

### Ingestion of Speed Report Once Captured
Once `captured/speed_report.csv` is produced:
```bash
cd backend
python scripts/import_speed_report.py ../captured/speed_report.csv --model-name yolov8n-person-ppe
```
This automatically populates the `pipeline_runs` table with verified metrics under `data_origin="live"`.
