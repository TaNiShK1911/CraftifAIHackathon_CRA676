## 2. Data Provenance Architecture

Every event, incident, and pipeline benchmark run contains a `data_origin` attribute:

| Value | Origin | Handling |
|---|---|---|
| `live` | Live MQTT / JSON stream from running PipeGen DeepStream pipeline | Displayed with green `[LIVE]` chip; visible in live-only mode |
| `replay` | Re-published from capture using `scripts/replay.py` | Displayed with amber `[REPLAY]` chip |
| `seed` | Development seed data generated by `scripts/seed_demo.py --allow-synthetic` | Displayed with muted `[SYNTHETIC]` chip |

### UI & API Capabilities
- **API Filtering:** `GET /api/incidents?data_origin=live` and `GET /api/events?data_origin=live`.
- **Live Monitor Toggle:** Operators can filter the live incident feed between "All Origins" and "Live Only".
- **Incidents Table & Drawer:** Displays the `DataOriginChip` for every incident.
- **Pipeline Benchmarks Table:** Explicitly shows `Origin` column so imported benchmark reports are auditable.
- **Speed Report Importer (`backend/scripts/import_speed_report.py`):** Requires mandatory fields (`precision`, `fps`, `latency_ms`), never fills defaults, and marks imported runs as `data_origin="live"`.
